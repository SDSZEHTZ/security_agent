## 数据流（已实现）

`VerificationAgent(verify_sqli/verify_ssrf)` 产生带 `verification_mode=DEMO_FIXTURE` 的 `Observation.data`。Supervisor 将 Observation 写入 State，EvidenceExtractor 识别标记后直接返回空列表。若 Task 存在对应 Finding，FindingEvaluator 仅根据已存在 Evidence 评价，不会由演示响应制造新证据。Task `COMPLETED` 仅说明此次模拟执行返回正常，不说明漏洞已确认。

PlanningContextBuilder 保留模拟 Observation 的任务 ID、执行状态及 `verification_mode=DEMO_FIXTURE`，但不将其响应码、布尔信号、潜在漏洞或原始响应传给 Planner。State 中的原始 Observation 保留供审计；非模拟 Observation 继续使用原有白名单过滤。

**限制：** 此方式防止内置模拟结果被误用，不是通用的可信来源证明。外部恶意 Agent 可能伪造没有标记的 Observation；真正的强信任边界应通过 Runtime 维护工具调用回执或带来源的可信证据模型来建立。当前项目未实现真实 SQLi/SSRF 验证，不应声称已经解决恶意 Agent 伪造证据问题。

## 验收命令

在仓库根目录：

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python -m unittest discover -s integration_tests -v
python main.py --target ./demo_app
```

使用 PowerShell 时亦可使用上述命令。实时 API 集成测试默认跳过，需要单独设置 `RUN_LLM_INTEGRATION=1`、`OPENAI_MODEL`、`OPENAI_API_KEY` 后再运行；切勿在公共 CI 中配置外部攻击目标或泄漏密钥。
